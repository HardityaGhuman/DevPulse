**DevPulse** is an AI-powered developer intelligence platform built around a team's GitHub workflow. It delivers instant code reviews, full pull request analysis, and scheduled activity digests — all generated by Google Gemini.

---

## The Problem It Solves

Code reviews take time, and keeping up with a team's day-to-day GitHub activity is tedious. DevPulse acts as an automated "AI assistant developer": it reviews code snippets on demand, analyzes entire pull requests for bugs and security risks, and emails developers a clean, AI-written summary of their recent GitHub activity on a schedule they choose.

## Key Features

- **AI Code Reviews** — Paste a snippet and get structured feedback: an overall summary and score, bugs by severity, security findings, improvement suggestions, complexity rating, and what was done well.
- **AI Pull Request Reviews** — Provide a GitHub PR URL; DevPulse fetches the diff and returns a per-file verdict, risk level, flagged bugs, and a merge recommendation.
- **Shareable Reviews** — Every review is saved and can be shared publicly through a unique, unguessable token, without exposing the rest of a user's history.
- **GitHub Activity Dashboard** — Authenticated users see a rollup of their recent activity: commits, PRs opened and merged, issues, reviews, and active repositories.
- **Automated Developer Digests** — Opt into daily or weekly email summaries. An AI coach turns raw activity into a headline, highlights, a momentum read, and an actionable tip.
- **GitHub OAuth via Clerk** — Sign in with GitHub; DevPulse uses the connected account to read repositories, PR diffs, and activity on the user's behalf.

---

## How It Works

DevPulse is a decoupled client–server application: a React single-page app talks to a FastAPI service over a JSON API.

### The flow

1. **Authentication** — Users sign in with GitHub through Clerk. The frontend attaches a Clerk-issued JWT to every API request. The backend verifies that token against Clerk's JWKS endpoint and looks up (or auto-provisions) the matching user record.
2. **GitHub access** — On first authenticated request, the backend pulls the user's GitHub username and OAuth access token from Clerk, then uses the GitHub REST API to fetch repositories, PR diffs, and event activity.
3. **AI analysis** — Code, PR diffs, and activity data are sent to Google Gemini with purpose-built prompts that return strict JSON. The backend parses and stores these structured results.
4. **Persistence & sharing** — Reviews and digests are stored in PostgreSQL (Supabase). Each review carries a share token so it can be opened by anyone who has the link.
5. **Scheduled digests** — A background scheduler runs once a day on the backend. It selects users due for a digest (daily users every day, weekly users on their chosen day), generates an AI summary of their recent GitHub activity, saves it, and emails it.

### Tech stack

**Frontend** — React + Vite, Tailwind CSS, Framer Motion for animation, React Router, and Clerk for authentication.

**Backend** — FastAPI (Python), Supabase (PostgreSQL) for storage, Google Gemini 2.5 Flash for all AI generation, APScheduler for the recurring digest job, and Resend for transactional email.

### Architecture highlights

- **JWT auth via Clerk** — The backend never holds passwords; it trusts Clerk-issued JWTs, verified through Clerk's JWKS, to secure every protected route.
- **Background scheduling** — APScheduler runs the digest job asynchronously inside the FastAPI process, aggregating activity and dispatching emails without blocking the request path.
- **Split deployment** — The stateless frontend runs on Vercel's edge network, while the long-running Python backend — which needs a continuously alive process for the scheduler — runs as a dedicated web service.
